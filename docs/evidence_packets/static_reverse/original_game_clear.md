# 通关谢幕（GameClear，关卡 998）的段落、时长、滚动、跳过与字串来源

> evidence: static-derived; resource-derived: obj-998.obs、PROCESS.DEF、RESOURCE.TXT、SHP 头 · status: live · functions: 0x4123b0, 0x42b130, 0x42b2b0, 0x42b6b0, 0x42ba10, 0x42bc20, 0x42c250, 0x42cc10, 0x42dc90, 0x43e2a0, 0x43e2d0, 0x4477b0, 0x453ac0, 0x45eb9d, 0x45ebdc, 0x4606a9, 0x46098f, 0x4609c0, 0x460a06  · tools: hsltools/assets/title_assets.py · updated: 2026-09-28

## 结论

- 通关谢幕全部由 obj-998.obs 的四个物件过程驱动：BOSS `defProcClearBOSS`（74 → `0x42b6b0`）排段，`defProcClearShowWorkTeam`（76 → `0x42bc20`）滚 OVER001／OVER002／WORKTEAM，`defProcClearShowPlayer`（75 → `0x42ba10`）逐个滚九位主角（过程表 `0x477c2c`，第 74–76 项＝`0x42b6b0`／`0x42ba10`／`0x42bc20`）（static-derived）。
- 时长以主循环 tick 计（16 ms，[tick 率](../runtime_observations/original_tick_rate/README.md)）：开场变亮 96 tick；OVER001 从 y=500 以 0.5 px/tick 上滚 1100 px（约 2200 tick）滚出画面上沿；独白前压黑 96 tick；OVER002 滚 668 px（约 1336 tick）；主角每位 1 px/tick、锚点到 y≤100 时下一位出场；最后一位之后 240 tick 出 WORKTEAM，0.5 px/tick 滚 1460 px（约 2920 tick）到底边贴齐画面底后停住（static-derived）。
- **制作群没有运行时字串**：WORKTEAM.SHP（640×1440）整张就是制作群与「劇終」，过程只滚这张图（static-derived）。运行时字串只在主角展示段：`0x42b2b0` 为九个槽各拼一张 FONT.24 状态单（RESOURCE 字串 37 姓名、41 力量、54 攻擊力……2568「此角色未加入隊伍」），`0x4123b0` 画在主角锚点左下（static-derived；resource-derived）。
- 跳过：BOSS 只在最后一个状态（19）读输入；此前没有任何跳过或加速，独白逐句由剧情 VM 的按键确认推进。制作群停住后按键（`[0x4c6390] & 0x600010`）或点击（`[0x4c6398] & 0x10002`）→ `0x42cc10(0,0)`：下一关 0（标题），`0x42dc90(2)` 每 2 tick 一级压黑 32 tick 后换场（static-derived）。

### 滚动（`defProcClearShowWorkTeam` `0x42bc20`）

- 初始化：`+0x90 = 500`（y），`0x45eb9d(0xc0, 0x8000, +0x34)`：角度 0xC0（表 `0x4a35fc`／`0x4a39fc` 第 0xC0 项 = 0／−0x10000）× 速度 0x8000（16.16 的 0.5）→ vx 0、vy −0.5 px/tick。`0x4606a9(帧, &原点x, &原点y, &宽, &高)` 取图高 H；剩余路程 `+0x94 = 500 + H + 80`（Data8≠0：OVER001／002，滚出上沿再多 80 px）或 `500 + H − 480`（Data8=0：WORKTEAM，底边贴齐 480 停）。
- 每 tick：x = 镜头 x，y = `+0x90` + 镜头 y；`0x45ebdc` 把 16.16 速度累加到 16 位小数位，整数部交替 −1／0；`+0x94 > 0` 时 y 与剩余同减。剩余 ≤0：给 BOSS `+0x8c` 加一；Data8≠0 的自删（`0x45e3ed`），WORKTEAM 留在原位。
- 形状原点（SHP 头 +28，manifest `draw_origin`）：画面左上＝物件位置 − 原点。

### 过渡

- `0x4609c0(n)`／`0x46098f(n)` 设方向与每级重装值，`0x460a06` 每 tick 计数，归零时级 ±1；级 0–16，16 为全黑。开场变亮 16→0 用 96 tick；回标题 `0x42dc90(2)` 压黑 32 tick。
- 对象 700（`0x43e2d0`，[tick 计数 §5](original_tick_counts.md)）：`+0x94` 的高低字为每级重装与首段计数，这里 0x60006 → 每 6 tick 一级。

## 重制接线

`game/title/GameClearScreen.gd` 按上表以 16 ms tick（`OriginalTick`）推进：开场变亮 96 tick、OVER001／OVER002／WORKTEAM 的起点、0.5 px/tick 与路程、独白段压黑与 120 tick 后换 OverBG02、主角每位 1 px/tick 与 y≤100 放行、240 tick、制作群停住后才接受按键、回标题压黑 32 tick；主角段九个槽都走，形状取 `combat_animation` 的战斗形状第 0 帧，状态单用 RESOURCE 字串按上表拼行、FONT.24 画（值由交接方给出）。`tools/hsltools/assets/title_assets.py` 的 `GAME_CLEAR` 改记这些数字与出处。

## 边界

- 没有原版谢幕录像；tick 数与滚动均为静态读法，未与运行画面逐帧对照。
- `0x4123b0` 第 6 参数 26 按行距读，未逐指令核完。
- 转职后的战斗形状（`0x4c1b6c` 表）重制按单位当前角色 id 在 `combat_animation` 里找，找不到退回基础 P00N；复活次数重制没有记录，显示 0。
- 独白段对白板、肖像与 STORYOVER 延时单位沿用 [尾声独白](original_game_clear_epilogue.md) 的读法；对象 700 每级重装 6 tick 是按 `+0x94` 高低字的读法。
- 开场前（STORY082 → 998 换场）与回标题后的画面由各自的换场路径负责，不在本包。
