# AI 呼叫目标：广播、消费与共享行动

> evidence: static-derived · status: live · functions: 0x40ba20, 0x40bb80, 0x40bee0, 0x40c110, 0x45ec32 · tools: hsltools/probes/ai_call.py, run_ai_call_tests.gd · updated: 2026-09-14

2026-09-14 / SR-036。接续 `a4f1197` 的来源目标／进攻类别规则。本包的原指令结果是 **static-derived**：用合成对象执行原 EXE 的有界函数／前段，不是原作自然战斗的 runtime-measured 样本。

## 原指令核对

`hsltools/probes/ai_call.py` 仅接受现有固定 SHA-256 的 hsl01.exe，复用已有 PE 映射入口。`original_ai_calls.json` 保存 40 组可独立重算结果：28 组 `0x40bee0` **正常返回**，12 组 `0x43f6c2` 进入的 **caller prefix**。原 `0x40ba20` 和 `0x45ec32` 同时实际执行，无成功值 stub；每组最多 8192 条指令。全部合成对象／角色内存与允许的目标 word 写入比较，不能顺带改 HP、资源或其他角色字段。

广播 `0x40bee0..0x40bf66` 遍历 200 个槽，跳过空槽和自己，双方 `0x870000` 阵营掩码必须**精确相等**，使用包含边界的圆形距离。它直接覆盖收件对象 `+0x8a` 的 word；没有检查 removed 位或 HP。半径零的 helper 仍可写入同坐标对象，但实际 caller 的 `ai_call_range == 0` 会跳过整个广播调用。夹具覆盖 3–4–5 圆边界、圆外对角格、相交但不相等的阵营、非阵营 flag、removed 对象、空槽和旧标记覆盖。

普通目标查找的返回值由 `0x43f6c2..0x43f6c6` 写入 `+0x88`。返回非零时，按 `+0x1cc` 呼叫半径广播，**不消费自己的旧 `+0x8a`**。返回零时，才读取呼叫标记、写入当前目标并清空标记。采用呼叫目标的路径不重新检查自己的 `find_range`，也不在这一分支重新广播。

`0x43f709..0x43f737` 检查呼叫对象是否为空、removed，以及排除 word 与对象 `+0xa2` 的比较。这里的排除零值代表不检查，读取的也是 **object word**，不能自动当成 `0x40bb80` 读取的 actor SID。失效时当前目标归零，然后进入 `0x40c110`。prefix 分别停在调用该未知辅助处理之前的 `0x43f73e`，或准备技能桶之前的 `0x43f74e`；未把这些停止宣称为完整 AI 正常返回。

现有旧文字“`0x43f660` 先消费标记”已更正：该位置属于等待回合检查的尾部；真正的标记采用在 `0x43f6e6` 之后。更早 `0x43f544..0x43f5f5` 还保留已有目标、检查距离与锁定范围，该完整持有／等待状态机不属于本包的 live 接入。

## 正式 PlayLoop 行为

`AICallRules` 提供无 RNG、无状态修改的收件者计算和普通搜索／呼叫选择分支。每个单位的 `ai_call_target_id` 是 PlayLoop 现有单位记录中的一项数据，不是第二份战斗快照。新战斗和增援初始化为空；广播根据**行动前坐标**计算，在成功行动事务中写入稳定单位 ID，后来的呼叫覆盖旧值。

AI 准备阶段同时验证可能采用的呼叫目标，包括超出接收者源搜索半径但仍可施法的目标。普通目标优先；没有普通目标才消费呼叫。目标选择后继续使用现有移动包络、武器范围、公共技能拥有权／禁魔／MP/ST／效果与状态收尾，发出一次行动收据并交接一次队列。没有可用目标仍结算一次 Wait。坏标记类型、重复单位 ID 或目标所需技能数据损坏，在 RNG 之前返回命名错误，不消费标记、不广播、不改变单位／资源／队列。

以下属于**明确重制适配**，不伪装成原指令等价：

- 源 side 使用现有 live 角色阵营映射；不把“友军”字符串证明为全部原 pm 位。目标必须是当前存活敌方，并继续应用已有 actor SID 预排除。原 caller 的 object+0xa2、零哨兵差异独立保留。
- 已死亡／离场单位不参与 live 广播，即使原广播 helper 本身没有 removed 过滤。普通击杀、范围技能结算、剧情离场和战斗终局都会清理失效引用；终局全部清空。重排 roster 不会令稳定 ID 指向另一个槽位，新增援不继承旧呼叫。
- 呼叫写入与成功行动一起发布；原引擎的分帧目标获取、锁定、等待和辅助处理时序没有由此复刻。位置选择与技能评分仍沿用已标明的重制策略。
