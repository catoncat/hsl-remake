# 原作贡献、击杀与最终 EXP 发放

> evidence: static-derived · status: live · functions: 0x40a5d0, 0x40aa80 · tools: hsltools/data/progression.py, hsltools/probes/experience.py, run_magic_experience_tests.gd · updated: 2026-09-28

## 结论

- 原版经验按每次动作结算：每个目标的实际效果贡献经 `0x40a5d0` 换算，整次动作合并后加倍入账，再查升级；没有整场胜利经验池（static-derived；原指令执行）。
- 重制 `ExperienceRules` 按同一换算提案、PlayLoop 唯一提交（static-derived）。

## 证据

机器入口 [original_experience.json](original_experience.json)，执行器 `tools/hsltools/probes/experience.py`。SHA 锁定的原 EXE 在隔离 Unicorn 内存中实际运行：73 次 `0x40a5d0` 正常返回、30 次最终发放／击杀状态后缀、8 次新增状态贡献观察。后两类不是整函数返回，不包含 UI、操作系统或队列回调；没有替换原 callee。

## 结算单位不是整场胜利

原 `0x40aa80` 对每个目标清空 `0x4c13fc`，累积实际效果贡献，在 `0x40b853` 调用 `0x40a5d0` 后返回该目标的经验。地图法术 caller `0x443100` 把各目标返回值加入同一 `0x4c2c7c`；施法起点 `0x442b7b` 清空该累积量。整次演出后的 `0x4427a9..0x4427e7` 才应用经验加倍、加到 actor+0x88，随后检查阈值／升级。

因此当前实现按**每个目标效果→该目标经验→下一目标→整次动作合并发放→成长**处理，不在撤离、最后一击或胜利页面再次分配整场贡献。此处“最终发放”是该次动作的入账，不是另造胜利经验池。原其他剧情奖励不在这个结论范围内。

## 贡献是什么

| 效果 | 进入换算的贡献 | 依据 |
| --- | --- | --- |
| 普通／特殊技／攻击法术 | 实际扣除 HP，不能以过量伤害刷取贡献 | 魔法 [原伤害包](original_magic_damage.md)，原普通交锋 `0x442c90` 后相关调用；特殊技复用目标贡献入口 |
| 治疗 | 实际恢复 HP 整除 2 | [支援前段](original_support_magic.md)，`0x40abec..0x40abfe` |
| 驱毒 | 清除前剩余回合数加 1，再乘 12；无毒为 0 | `0x40b3a6..0x40b3ec`，支援包的24个应用前段包含清除及不清除 |
| 中毒 | 本次真正增加的持续回合 ×10 | `0x40ad75..0x40ad91`；新原前段结果包含2/8/9回合合并，已到9回合时不会按请求时长发奖 |
| 禁魔 | 本次真正增加的持续回合 ×5 | `0x40aeae..0x40aebf`；伤害致死后不再施加状态，因此不产生该部分贡献 |

治疗／驱毒先前保存在收据的 `native_contribution` 现在实际进入这条换算链；它本身仍不是最终 EXP。

## 原换算顺序

以下是已执行正数域的整数模型。`C` 为本目标贡献，`K` 为死亡目标的 `kill_exp`（存活为0），`d=施放者等级−目标等级`。`rand(n)` 返回0到n−1；原 `rand(0)` 仍走生成器并返回0（不推进伤害流，见[伤害随机流](original_damage_random.md)），不能在回放中删掉该次调用。

```text
C == 0: EXP = 0，完全不抽样
d >= 0:
  A = (floor(C*40/100) + K + rand(floor(C/2))) * 100
  B = floor(A / (max(1,min(5,d))*80))
d < 0:
  B = min(5,-d)*C + K
P = max(1, B-rand(floor(B*30/100)))
目标死亡时:
  P = floor(P*(100+min(8,既有击杀连续数)*50)/100)
```

73组正常返回覆盖无贡献、低贡献的零界限抽样、上下等级差和上限、击杀奖励、0–9连续数及带高字的记录。Godot 逐次重放原样本和抽样界限。产品使用自身显式 RNG，不声称和 Wine 全局随机流同种子完全一致。

## 击杀连续数与装备

actor+0xa8 的低16位是连续数，高位0x10000标记本次行动是否击杀。当前目标先按旧值换算；随后首个死亡目标增加连续数，后续范围目标会看到新的连续数。范围法术总击杀数逐个增加，但同一次法术只推进一次连续数。自己的行动结束时，有标记就保留低字，无标记归零；移动／查看／取消不结束行动，Wait、非击杀支援等会正常断开。非致死反击清空反击者的连续数，致死反击沿原后缀增加。

源 `ITEM.exp_x2` 在 `0x447e40..0x447e61` 映射为0x10。最终发放后缀按这个位把整次经验乘2，再加入现有经验；多件相同位不叠成4倍。当前源物品228「幸運緞帶」已进入受支持换装，详情和确认预览显示真实经验倍率；装备本身不赠送经验，取消不改变倍率。

升级门槛 `min(2000, (level+1)*50)`：`0x44b678` 把等级 `+0x9c` 加 1 后乘 5、5、2，夹到 2000 写入 `+0x8c`；升级路径 `0x43a235..0x43a243` 从 EXP `+0x88` 减去该门槛，溢出保留（static-derived；两段原字节可用 `PYTHONPATH=tools python3 -m hsltools.data.progression --check --check-exe <hsl01.exe>` 核对）。

## 重制接线

`ExperienceRules` 只计算提案，PlayLoop 是唯一提交者。技能全目标、经验数值及装备数据在 RNG 前验证；同一次施法不能在中途升级、修改魔击力或再次扣费。普通主攻／反击先完成本次交锋效果，再各自一次发放；被反击击倒的攻击者不获死后成长。死亡、奖励去重、物品领取、剧情与原有动作交接继续共用同一状态。

`ProgressionRules` 现在只接收已换算和加倍后的最终量，不再执行“实际伤害+kill_exp”。原阈值、五点预算和已支持 SwordMan 刷新保留。原零剩余成长容量会放弃EXP；因为重制允许暂存点数，当前把未分配点数视作已占用容量，防止最后三点被反复记成多个空升级。这个暂存组合是明确重制策略，不伪称原即时分配界面。

当前只有已有成长模型的角色真正入账并升级；无模型的NPC仍保存完整原换算依据，返回 `unsupported_growth_model` 而不冒充已恢复其派生数值。角色初始化、全职业成长、全原全局随机流、特殊技伤害输入及完整死亡 handler 仍独立保留边界。公开参数限定为经过校验的当前正数域，不承诺畸形／signed溢出输入与原引擎一致。

最终EXP、连续数、总击杀、成长预算与收据由原单战存档共同保存。F9恢复、奖励领取、重复结局判断均不重发；最终击杀所得未用点数留在终态存档，不因无法在结果页立即加点而丢弃。配置摘要变化会拒绝旧配置存档，不静默补造新字段。

## 复现

`python3 tools/hsl.py check experience`

实际控件、图片和默认路线结果见 [魔法与经验验收](../runtime_observations/magic_experience/README.md)。保存的原返回检查、Godot规则通过、图证可读与全游戏等价是不同结论。

## 边界

- 后两类原指令执行是后缀，不是整函数返回，不含 UI、操作系统或队列回调。
- 无成长模型的角色返回 `unsupported_growth_model`；角色初始化、全职业成长、全原全局随机流、特殊技伤害输入及完整死亡 handler 不由本包证明。
- 暂存点数占用成长容量是重制策略（provisional）。
