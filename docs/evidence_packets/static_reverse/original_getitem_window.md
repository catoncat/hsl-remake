Checked: 2026-09-21。同 [升級窗包](original_growth_window.md) 的 EXE／PAK 来源与读法；没有 Wine 执行。本包只回答「击杀掉落后原版画什么、怎么拾取放置、三个按钮做什么」，是 `BattleLootPanel.gd` 的布局合同来源。掉落资格与随机流见 [战斗奖励来源](battle_reward_inputs.md)，待领池函数名见 [宝箱包](original_treasure.md)（`0x44f290`／`0x44f2d0`）。

## 1. 入口

`0x442720` case 4（`0x4428b8`–`0x44290e`）：金钱浮字后，若待领池非空（`0x44f4d0() != 0`，池 = `*0x4c1d28` 的 (code, qty) 对，计数 `*0x4c1d2c`）：

- 击杀者是玩家对象（kind 3）→ `*0x4c2ae4 = 击杀者槽`（本窗**唯一**接收者，不能切换成员），`0x436490(actor,0,0)` 生成文字，`0x43b4e0(actor,0xb,…)` 打开状态窗 **mode 0xb**；
- 否则 `0x44f600(actor)`：把池中物品逐件塞入击杀者背包（`0x436e30`），塞不下的留池，随后 `0x44f4e0()` 释放池（NPC 击杀不开窗）。

所以窗在 EXP、金钱浮字之后、升級判定之前出现，接收者固定为击杀者。宝箱路线由 `0x4156d0` 把内容加入同一池后走同一窗（[宝箱包](original_treasure.md)）。

## 3. 待领列表 `0x414c00`（defProcGetItemWindow，与商店窗同函数）

初始化：顶缘偏移 `+0x9a = 0x2b`（43），行距 `+0x98 = 0x20`（32），滚动起点 `*0x4c1a5c = 0`，滚动条 `0x446060` 范围 = 池计数。

每 tick 绘制（坐标以窗左上 (252,168) 为 (x,y)）：

| 元素 | 位置 | 内容 |
| --- | --- | --- |
| 标题 | `0x4128f0(x+32, y+10, "@6"+资源313, …, 26)`：26 半角宽字段内居中 → 「獲得物品」8 字节起于 x=392 | 米白 `@6` |
| 行 i（0..4，最多 5 行可见） | 图标 `0x4607f9(x+32, y+43+8+6+32i, ICON[type])`（中心 (284, 225+32i)）；文字 `0x4123b0(x+56, y+43+8+32i)` → (308, 219+32i) | 每行 = 颜色码 + 名字（资源 `+4`，补／截到 14 半角）+ 两空格 + `0x45b6de(qty,…,7,' ')` 七位右对齐（数字右缘 x=584）+ `#` |
| 行颜色 | ITEM `+0xa0 & 0x8000000`（important）→ `@6` 米白；`+0xa8 & (1<<job)` 本职业可用 → `@1` 白；否则 `@2` 红 | job 位 = `0x4464f0(job)`，重制同 `EquipmentRules` 的 `1 << (job_code−80)` |
| 悬停行 | `hover = (mouse_y − y − 43 − 8) / 32`，0..4 | `0x430710(code)` 生成描述文字，`0x436d70()` 画描述框，并用 `0x4132f0(x+56, 行y, 描述前14字节, …, 1)` 把该行名字改画成 `@3` 绿 |

`0x438160` case 2 mode 1（左栏背包）同样：悬停 `(mouse_y − y − 8)/32` 0..7，有物品则 `0x430710`+`0x436d70`+绿字；图标中心 (44, 184+32i)，文字 (68, 176+32i)。

### 描述框 `0x436d70`

WINDOW50（`*0x4c2c98`，376×88）在 getitem 模式画在 **(252,390)**（`0x4c1cbc & 1`；状态页为 (252,349)），文字 `0x412060(x+8, y+12, buf, …, 0x2d, 0x10)`：15 号小字、45 半角宽居中、行高 16。`0x430710` 的内容：`@3`+名字；`@1#`；消耗品 → 「可使用」(79) + 生命／魔法／氣力／永久… 行、解毒／解痲痺／解封印 (114／113／115／168)；装备 → 攻擊／防禦／命中… 数值行与职业括号。描述框覆盖 y 390–478，即覆盖三个按钮——悬停物品时按钮看不见也点不到，移开即恢复（录像 `16/frame_003` vs `frame_006` 正是这两种状态）。

## 4. 拾取／放置流程

手持槽 `*0x4c1ce4`（一次一件）。`0x414c00` 点击（`in_stack & 0x40000`）：

| 状态 | 点待领列表 | 点背包格（`0x438160` case 2 mode 1） | 右键／Esc（root case 1） |
| --- | --- | --- | --- |
| 空手 | 悬停行有物 && `0x40e690(code)==0`（非重要）→ `*0x4c1ce4 = code`，`0x44f430(idx,1)` 池中 −1，音 **399 TAKEUP01**；重要物品**不能拾起** | 格有物 → 拾起该物（`0x436e80`），音 399 | 关闭窗（被 `0x400` 位挡住，static-derived） |
| 手持 | `0x44f2d0(held,1)` 放回池，`*0x4c1ce4 = 0`，音 **400 PUT00003** | 空格 → 放入（`0x436e30`），音 400；有物 → 交换：格物进手、手物进格，音 400 | `0x436e30(actor, held)` 自动放入首个空格，音 400 |

## 5. 三个按钮 `0x43a640`（defProcStatusButton）

- 外观：42×42 图标，中心即停靠点；标签 = 资源 Data9 文字，用 15 号小字画在 `(中心x − 21 + (42 − len·8)/2, 中心y + 13)`，白 `0xffff`／悬停黄 `0xffef`，阴影 0x8430。点击音 398 ACCEPT01。
- 丟棄（Data6=6）：手持且非重要 → `*0x4c1ce4 = 0`（**只丢手上这一件**，永久消失）。空手无效。
- 倉庫（Data6=7）：手持 → 重要走 `0x44ef70`、普通走 `0x44f100` 加入队伍仓库表（`0x4c1d10`／`0x4c1d1c`），清手。空手无效。
- 離開（Data6=8）：**空手**才有效 → root `+0x96 = -1` 关闭。`0x414c00` case 1 收到关闭：非商店模式 → `0x42aad0()`：池中剩余全部按重要／普通加入仓库表，再 `0x44f4e0()` 释放池。即原版离开时不丢任何物品，剩余物进倉庫。

## 7. 重制映射与保留差异（`game/battle/scene/BattleLootPanel.gd`、`BattleSettlementController.gd`）

| 原 | 重制 | 备注 |
| --- | --- | --- |
| 接收者 = 击杀者／开箱者，不能切换 | 同：控制器按 `kills[0].attacker_id`／`owner_id` 定接收者；从状态页重开时接收者 = 状态页所看成员 | 删除成员下拉 |
| WINDOW20 (12,168) 背包 8 格、WINDOW90 (252,168) 5 行、WINDOW40 (20,442)、描述框 (252,390)、三按钮 | 同坐标、同资源、同字号级（24／15 → 系统字 22／14） | 字体族不同（无 FONT.24 位图导入） |
| 行 = 名字 + 数量 | 待领实例按 code 归并显示数量；拾起取该 code 首个实例 | PlayLoop 待领池是逐件实例 |

| 右键／Esc：空手→不关闭 | 同（无动作） | |

| 步骤 | 操作 | 应看到 | 对照帧 |
| --- | --- | --- | --- |
| 1 | 雷歐納德 用 攻擊 击杀携带物品的敌兵（第一战 敵兵 有 回復藥／解毒草 掉落），等 EXP／`$` 浮字结束 | 全屏 獲得物品 窗：上方 WINDOW10 生命条＋姓名窗为**杀敌者**；左 WINDOW20 八格背包；右 WINDOW90 标题「獲得物品」居中、每种物品一行「图标 名字 …… 数量」；左下 `$:` 现金；下方三图标 丟棄／倉庫／離開 | `frame_006`（按钮可见） |
| 2 | 鼠标停在待领行上 | 该行名字变绿；WINDOW50 说明框出现在 (252,390) 覆盖三个按钮，三行居中小字（名字绿／可使用／效果） | `frame_003` |
