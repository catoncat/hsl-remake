## 来源与可复跑边界

`resource-derived` 的箱内物品来自原 `LEVEL001.BIN`／`LEVEL002.BIN` 的 EVEF 实例；`static-derived` 的复制、接触、领取与初始化来自匹配 SHA256 `f0b5f835d7d0d311b3ed75049c9fc2adc2b470b2bb30700e593abedf8c0a70f7` 的 `hsl01.exe`。实际执行结果在 [original_treasure.json](original_treasure.json)，工具为 `tools/hsltools/probes/treasure.py`。默认只离线验证；显式 `--execute <原EXE> --write` 才重跑有界原指令。原包及 EXE 均为只读输入。

原 `PROCESS.DEF` 的 `defProcTreasureBox=41` 经进程表 `0x477cd0` 指向 `0x415730`。关卡创建入口 `0x42dae7` 把 `0x42bd50` 作为 EVEF 实例回调；`0x46be68` 的遍历调用以208字节实例记录传参。箱内八个 DWORD 从实例 `+0x10` 读取，不由同名 OBS 模板、截图或掉落概率推断。OBJ-001／OBJ-002 的箱模板只提供形状及对象字段。本包将原 BIN／OBS 的完整 SHA 与现有 seed 再核对；指令锚点合并 SHA 为 `2c2f37da51627bf69ec280d48e07daa5f7b52acf76dc96dbd214ec9797a24e25`。

## 进关、再进关与读档

静态（`static-derived`）：新关入口 `0x42da60` 先调 `0x42c640`（其中 `0x42c6a4` 调 `0x44f4e0` 释放待领队列 `0x4c1d28`）等复位，读关卡后在 `0x42dad8` 调 `0x45e224` 清空整个对象池（池基址 `[0x4a19c0]`、个数 `[0x4a19c4]`、步长 `[0x4a19c8]`=0xb0，连同散列桶 `0x4a35ec`）。读档旗 `[0x4c1ae4]`=0 时 `0x42dae7` 以 `0x46be17(0, 0x42bd50)` 按 EVEF 重新建出全部对象，宝箱内容再从记录 `+0x10` 拷入；分配器 `0x45e307` 按模板 `0x4a2728[code]` 整块复制 0xb0 字节，所以新箱不带任何旧已开位。旗 bit31（回憶錄）同样走 EVEF 重建再 `0x42ec10(slot,1)`；其余非零值走 `0x42db43` 的 `0x42ebe0(1)`（戰場記錄），恢复的是存档里的战场对象，不重走 EVEF。删除器 `0x45e3ed` 只把对象还给池、不调用任何函数；已开位 `0x08000000` 只写在这只对象 `+0x80` 上。原版没有另外的全局／跨关开箱表：回憶錄块表（[original_save_format](original_save_format.md)）没有关卡对象块。待领队列还在交接 `0x407510` 的 `0x40751c` 处释放。`0x4156d0` 唯一调用点是玩家动作后缀 `0x44554c`，AI 行动不开箱。

整镜像实测（`runtime-measured`）：`tools/hsltools/probes/_treasure_reentry.py`（诊断，不注册任务）用 `_enemy_level.round_sort_machine` 让整个原映像经 `0x42da60`（读档旗 0）进关、停在首次回合排序 `0x407340`；同进程整段执行一次 `0x4156d0`（含 `0x44f2d0` 与 `0x45e3ed`），生成器入口 `0x458c10` 计次；再同进程调用 `0x42da60` 进同一关到首次排序，重读箱表。

## 隐藏宝物

**隐藏位来源（static-derived）**：画不画由箱子的**对象模板**决定——本关 OBS 里这个对象码的 `obj_Attribute` 有没有 `objattrATTACKFLAG`（PROCESS.DEF 第 76 行 `0x00010000`，resource-derived）。不是 EVEF 实例字：EVEF 记录只给码与位置。链路：

1. OBS 加载 `0x45dc5c` 把 `obj_Attribute` 写进模板 `+0x80`（[字段覆盖](original_field_coverage.md)）；
2. EVEF 遍历 `0x46be60` 以 `(x, y, 码, 0)` 调分配器 `0x45e307`，后者把模板 `0x4a2728[码]` 整块 0xb0 字节复制进新对象，再 `+0x80 |= 0xb0000000`（含待初始化位 `0x20000000`），`+0x54` 写码；
3. 对象调度 `0x45f636..0x45f655` 以 `过程表[+0x64](obj, obj[+0x80])` 调用——消息就是对象自己的 `+0x80`；
4. `0x415730` 见消息带 `0x20000000`：清该位、置 `0x100000`；消息没有 `0x10000` 时把形状字 `+0x30` 写成 `0xffff`。`0xffff` 是原版通用的“无形状／隐藏”值（同一写法见 `0x4287cc` 写 `0xffff`、`0x428795` 从 `+0x32` 复原）。

**模板普查（resource-derived）**：35 关 77 只箱中，只有 obj-028.obs 与 obj-080.obs 的 798 `寶藏` 写了 `obj_Attribute = objattrATTACKFLAG ; show shape`；其余各关 OBS 的 798 `寶藏` 与 obj-028.obs 的 26 `寶藏(隱藏)` 都没有这个字段。28 关记录 40、41 放的是码 26，不是 798（旧稿“同一对象码 798 两种都有”有误）。

**接触（static-derived）**：玩家动作后缀 `0x445526` 见 `+0x30`=`0xffff` 先 `0x4477b0(0xa05,0)`→`0x459990`→`0x42c180` 放声，再进 `0x4156d0`；可见箱直接进 `0x4156d0`，这一段不放声；`0x4156d0` 本身也不放声。`0xa05`＝2565＝resource.h `sfxGetTreasure`，RESOURCE 2565＝`WAV\EFF0014.WAV`（resource-derived）。

**整镜像实测（runtime-measured）**：`_treasure_reentry.py --census <关>` 进关停在首次回合排序，读每只活箱的码、模板 `+0x80`、形状字，并按像素连回 seed 的 EVEF 记录。35 关 77 只全部“模板 bit `0x10000` 决定可见性”，**隐藏 54、可见 23**；`--level 28` 的整段再进关逐只可见性与首次相同。28 关逐只：
