# 给视频分析模型的补充任务

> evidence: runtime-measured · status: record-only · updated: 2026-09-14

请基于原录像补充可验证材料，不再撰写“绝对还原规范”。已有 18 类接触表和关键帧足以导航，不必重新提取整套重复图片。原视频相对仓库根目录位于 `../hsl-fork-raw-archive-20260914-gameplay/record.mp4`；SHA-256 和录制参数见本证据包的 `manifest.json.source`。

## 第一批：补连续事件与准确边界

优先处理气刃斩、一次普通攻击、一次幻火、死亡→EXP／金钱／战利品、一次完整对白翻页。每个事件给出前置可见状态、从操作前到恢复控制后的连续片段、零起算源帧号／PTS、关键变化点及证据图片。原导出 `frame_054` 等只是采样编号；不要把它当视频帧号。

动画每一段至少记录：第一张可见帧、最后一张可见帧、角色／特效变化、HP 条／数字第一次变化、返回地图、下一次可见可操作状态。对眼横幅、持剑框、侧面框、线条、命中、受击、遗言分别标注。独立保留攻击者与受击者、UI 与地图的轨迹；不能拿鼠标停顿、玩家阅读时间或等待 AI 的时间当动画固有时长。

凡没有连续数据支撑的边界，给一个“最后未出现～首次出现”的时间区间，并写测量不确定度。30 fps 录像不能证明 30 Hz 游戏逻辑；不要插帧或用补帧画面作证据。

## 第二批：补信息显示与交互条件

确认普通攻击和气刃斩选目标分别显示什么；友军／敌军／空格／范围外、已侦察／未侦察时是否显示 `???`、真实 HP 或命中率。当前 08 目录实际是气刃斩，不要继续将其当普通攻击。

对白与状态页给稳定的完整原帧，再附坐标标注：边界、姓名基线、正文各行基线、肖像矩形、继续符号和遮挡区域。列明测量坐标是 638×480 录制像素；640×480 到录制图的裁切／缩放关系未知时不强行校准。字体家族要给资源来源，否则只描述形态。精确透明度需要已知背景与前景的受控样本，不能从压缩后单图猜 RGBA。

确认战利品完整操作：物品出现、取起、放入背包、部分领取、取消／退出，以及何时允许下一角色行动。已有录像没有某分支，就标“未录到”；不要从成功一次推满包、放弃或免费操作规则。KILL 的含义、EXP／金钱公式、技能费用和异常资格交给源程序研究，视频只记录实际前后值。

## 可交付的数据结构

每个观察独立一条，正文描述与推断分栏。下面是字段示意，不是已发生的事件：

```json
{
  "id": "unique-event-id",
  "source_sha256": "填写原视频SHA-256",
  "recording_size": [638, 480],
  "start_frame": 0,
  "end_frame": 1,
  "frame_convention": "zero_based_inclusive",
  "state_before": "填写可见事实",
  "input": {"observed": false, "description": "鼠标／按键无日志，不能猜"},
  "visible_changes": [],
  "state_after": "填写可见事实",
  "evidence_frames": [],
  "measurements": [],
  "inferences": [],
  "unknowns": []
}
```

每张图／裁切需带 `source_frame`、PTS、原帧 SHA-256、裁切矩形 `[x,y,w,h]`、是否缩放及图像哈希。短片需写源区间和导出方法；保留原帧率与音轨，不添加转场，不遮掉关键 UI，不使用超分辨率或生成补画。接触表每格标源帧号和秒数，不能只写导出序号。

如音频可分析，单列可听事件与源时刻、起止区间及与画面关系；从已有原声音资源识别需要给资源匹配依据。不得从受击姿势推“惨叫／骨折”音效，也不要把没有审听写成“无音效”。

## 真正需要新录制时

优先 640×480 原始游戏画面、无水印、未缩放、恒定帧率并保留音轨；只截游戏画面。记录版本／可辨版本信息、存档或复现起点、角色／装备／资源前值、明确输入与时刻。完整结尾不得录入桌面、聊天或终端。

现有视频中没出现的分支，另列为新录制建议：普通攻击落空／非致死／致死、技能不足资源、战利品满包／部分领取／退出、给予交换取消、成长确认。每次只解决一个可重复问题，不要求用户再完整打一遍，也不替项目创建游戏状态或更改实现。

验收标准：每条结论能定位到源片段；观察和推断分开；未录到就留空；数值与台词可读才转写。数据完整、图片真实、语义可信是三个分别检查的结果。
