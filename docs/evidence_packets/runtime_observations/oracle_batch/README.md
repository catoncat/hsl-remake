## 做法

- **原版侧**：`_enemy_level.py batch --levels <128 关> --seeds 1,2,3 --jobs 2 --align --no-remake --out DIR`。
  - 进关走 0x42da60，停在首个 0x407340 前。
  - `--align` 把重制同关、同盘面（`{"growth": false}`）的格子、HP、速度写进原版。
  - 全局流种子为 (s, s)。
  - 从第一个有人行动的轮起算。18、53、79 关停在第 1 轮的排序，第 2 轮才有人行动。
- **重制侧**：`_enemy_level.py batch --no-original --jobs 2 --out DIR`。等于每关每种子跑一次 `tests/export_enemy_turns.gd --battle <关> --turns 1 --seed s --state {"growth": false}`。
- **一致口径**：同一行动者的 from／to／action／target 四项全同，与 `_enemy_level.py compare` 口径相同。
  - 技能名不计入一致，另外列出。
  - 一格写作「一致行／总行」，总行是两边行动行的并集。
- **分类**：先按下面第 1 条挑出注入缺口，余下的差异行依次看第 2、3 步。
  1. **注入缺口**：
     - from 不同：原版在停点之后，开局事件又挪了位置。
     - 目标或行动者在重制名单之外：code069、code101 单位，或停点后才由事件装上的 `obj0x…`。
  2. **前缀**：
     - 取原版这一种子的首轮当期望，去掉重制没有的行动者。逐个检查重制各 AI 种子与期望的一致前缀。
     - 若有种子整轮复现期望，这一种子的全部差异都算随机。
     - 否则取最长前缀 j。原版第 j+1 行就是「跟着原版前缀，重制怎么也走不出来」的第一行。
       - 走到这一行的种子满足以下任一条件，就判规则（前缀确证）：≥10 个，且卡在同一字段；或 ≥3 个，且结果只有一种。
       - 另外还要求卡住的那个字段单现值占比 ≤ 0.1（Good–Turing 未见质量）。
       - j 之前的差异都算随机。
       - 1–21 关另有一份逐种子准备的 64 种子前缀搜索（任务中途停掉的旧法，每个种子各自 `prepare --seed s`）。搜索走得比 j 远，说明这个根能被复现，改判随机。12 关 s1、s3 两个站位根就是这样被推翻的。
  3. **边际**：剩下的差异行（j 处样本不够，或在 j 之后），看原版该字段的值在重制 32 个种子、同一行动者第 k 次行动的值里有没有出现过。
     - 从未出现，且该字段单现值占比 ≤ 0.1 → 规则（边际）。
     - 从未出现，但单现值占比 > 0.1 → 待定（覆盖不足）。
     - 出现过 → 随机。
     - 这个行动者在重制里行动不到 8 次 → 待定。
  4. 同一种子已有 from 不同的，其余差异都算待定，因为上下文已不可比。
  5. 原版行的 to 为空，且这一种子原版首轮内战斗结束 → 口径（战斗结束半行）。
- **复现度**：每条规则行另记「原版 3 个种子里，这个行动者第 k 次行动在规则字段上取同一个值的种子数」。≥2 说明原版这边也稳定，是两侧分布都不同的强证据；=1 只说明重制这边走不出来。
- **类别**：先看 action，再看 target，最后看 to。
  - action 不同：任一侧是法术 → 法术分支；攻击对待机 → 地形射程。
  - target 不同：原版是法术 → 法术目标；原版是待机 → 持有目标（待机时追的目标）；原版是攻击 → 选目标。
  - 只有 to 不同 → 站位。
- **与 ORACLE2 的偏差**：任务书要两边各跑 32 个种子。
  - 本批原版每跑一次约 4 s（这段时间机器负载 37–67），125 关 × 29 个种子约需 4 小时，所以原版只跑 s=1..3。
  - 重制侧每关只做一次 prepare（`--seed 1` 盘面），AI 种子 1..32 各跑整轮；2、3 关跑了 64 个。
  - 用 1–21 关的 64 种子前缀搜索对照：能对上的 10 个根里，8 个最长前缀与本法相同（3 关三个种子都是 2/14、卡在 target）；12 关两个被推翻（见第 2 步）。

## 规则类差异排行榜

各列说明：

- 「前缀确证」由第 2 步判出，「边际」由第 3 步判出。
- 括号里是边际行中落在某个前缀确证根之后的行数，这些行可能只是那处规则差异的后果。
- 「其中 ≥2 种子复现」见上文「复现度」。
- 「涉及行动者」按（关，行动者）去重。

## 局限

- **只验了单向。** 本批问的是「原版这 3 个种子走出的行，重制能不能走出来」。反方向要原版也跑多种子，本批没做，即「重制走出的行原版能不能走出来」。
  - 所以只在原版这边稳定、重制那边不稳定的规则差异会漏掉。例：ORACLE2 把 3 关 028_1 的站位判为规则（原版 16/16 走 [6,10]，重制在两格间分），本批这 3 个种子里，重制走过原版那一格，只能判随机。
- **边际检验看的是「出现过没有」。**
  - 如果重制 32 个值里单现值占比超过 0.1（Good–Turing 未见质量），「没出现过」就判待定，不判规则。这样站位这种取值多的字段不会因为样本少而被误判成规则。
  - 反过来，原版值在重制里出现过、只是概率不同的规则差异，会被判成随机。
  - 落在前缀确证根之后的边际规则行，可能只是前面那处差异的后果。排行榜单列了这部分。
- **重制分布只用了一个盘面准备**（`--seed 1`：伤害流、全局流从种子 1 起）。原版种子 2、3 的前缀里如果有命中或伤害分叉，重制分布里的那一段条件与之不同。这种情况下前缀走不到，差异落到边际检验。59 关魔王就是例子：重制分布里它一次行动后战斗就结束，主跑种子 2、3 则连动两次。好在施法决定发生在第一次行动、伤害之前，所以不受影响。
- **伤害流逐值没有对拍。** 两边的命中、伤害结果不同，会让后面的行动分叉，这类分叉按前缀算随机。
- **技能名不计入一致。** 一致行里技能名不同的另列在 JSON 的 `skill_only`。
- **待定**有三种来源：该行动者在重制里行动不到 8 次、同一种子已有开局格不同、边际覆盖不足。本批的 7 行待定都在 18 关，都属于开局格不同。

## 复现

```sh
export PYTHONDONTWRITEBYTECODE=1
UV="uv run --no-project --with unicorn==2.1.4 --python /opt/homebrew/bin/python3 python3"
$UV tools/hsltools/probes/_enemy_level.py batch --levels <关表> --seeds 1,2,3 --jobs 2 --align --no-remake --out DIR
$UV tools/hsltools/probes/_enemy_level.py batch --levels <关表> --seeds 1,2,3 --jobs 2 --no-original --out DIR
```

关表就是 `content/generated/hsl/development/autoplay/results.json` 的 128 个关号。

`BATCH` 结果行：

- 原版侧：`BATCH levels=128 seeds=3 jobs=2 original_wall=287.6s total_wall=287.6s`
- 重制侧：`BATCH levels=128 seeds=3 jobs=2 original_wall=0.2s total_wall=1752.8s`

重制分布这一步用的是 ignored/ 下的本地脚本：先做一次 `_prepare`，再改 AI 种子跑 `_play`，与导出器 `--search` 的做法相同，只是每个种子都跑整轮。这一步没有进仓库。要复现，可以对每个 AI 种子 N 单独跑一次导出器：`--battle <关> --turns 1 --seed 1 --ai-seed N --state {"growth": false}`。完整的逐次 jsonl 也留在 ignored/，没有提交。
