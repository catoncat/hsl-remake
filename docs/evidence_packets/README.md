# Evidence Packets

Tracked evidence is intentionally small and decision-oriented. Raw captures, temporary dumps, long decompilation output, and generated comparison galleries do not belong here.

Current packets:

- `runtime_observations/first_battle_visual_evidence_index.json` and `first_battle_visuals/`: the curated original-runtime screenshots required by camera, projection, Move, hit-test, menu, and opening work.
- `runtime_observations/first_scene_opening_choreography_packet.json`: the bounded opening-segment contract; it records what can drive runtime presentation and what remains missing.
- `resource_inventory/resource_manifest.json`: the full machine-readable resource-member index. Query it with `rg`, `jq`, or tools; do not load the whole file into an Agent context unless necessary.
- `resource_inventory/original_scope_inventory.md`: resource-derived counts of the whole original (levels, scripts, tables) against the remake campaign registry, with the planning order derived from them; regenerated by `tools/hsltools/data/scope_inventory.py`.

New evidence enters this directory only when it has a clear claim boundary, source/provenance, machine-readable form where practical, and a checker or repeatable validation route.

## Packet header

Every packet (`*.md` under `static_reverse/`, `runtime_observations/`, `resource_inventory/`, recursively; this README is the directory index, not a packet) carries one machine-readable line directly under its H1 title:

```text
> evidence: static-derived; provisional: synthetic initialization · status: live · functions: 0x448840 · tools: hsl_native_stats_probe.py · updated: 2026-09-10
```

| Field | Rule |
| --- | --- |
| `evidence` | one or more of the seven tiers separated by `; ` — `resource-derived` / `static-derived` / `runtime-measured` / `user-confirmed` / `user-hypothesis` / `provisional` / `negative-evidence`; a tier may be scoped with `: <which part>` (`provisional: 合成初始化`). Multi-tier packets list the packet's own primary tier first. |
| `status` | `live` — the body names a `game/` module, `*Rules`／`*Runtime` class or `tests/` suite that consumes the packet (runtime_observations receipts of the remake count as live); `record-only` — index, audit, original-only observation or history with no runtime consumer; `superseded: <relative path>` — replaced wholesale by that packet (target must exist). |
| `functions` | optional; original `hsl01.exe` function entries `0x4xxxxx`, lowercase, unique, ascending. Instruction anchors and data tables stay in the body; `--lint` flags addresses missing from `content/generated/hsl/static/hsl01/function_catalog.json`. |
| `tools` | optional; repro entry points as file names under `tools/` or `tests/` (probes, generators, checkers, capture/run suites), unique, sorted. Generic launchers (`godot.sh`, `play.sh`, `verify.sh`) are not entries. |
| `updated` | `YYYY-MM-DD` — when the packet's content last changed. |

Fields keep this order and are separated by ` · `. The header is the single source of truth: `python3 tools/hsl.py check evidence_index` (in `tools/verify.sh` via `tools/verify_runner.py`) validates every header and confirms the generated block at the end of [`docs/KNOWLEDGE_INDEX.md`](../KNOWLEDGE_INDEX.md#evidence-packet-index) is current; `--write` regenerates that block; `--json` prints all headers for programs (no tracked `index.json` — nothing consumes one); `--lint` prints non-failing hints (unknown functions, missing tools, body tier words the header does not declare). Body prose keeps its own tier sentences; the header only makes them machine-checkable, it does not upgrade them. Generated packets (`campaign_overview.md`, `first_scene_opening_choreography_packet.md`) get their header from their generator.

Workflow for a new or changed packet: write or edit the header line → `PYTHONPATH=tools python3 -m hsltools.evidence.index --write` → commit the packet together with `docs/KNOWLEDGE_INDEX.md`.
