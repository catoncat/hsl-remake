# 怎么核对

重制版和原版一不一样，由原版程序说了算。本页讲这件事怎么落地：裁判怎么跑，证据怎么分级，差异怎么记，哪些地方有意不照原版。

## 原版程序当裁判

规则层的每一条"和原版一样"，最后都拿原版程序本身来对。裁判在进程内用 CPU 模拟器把原版程序整个跑起来，走它自己的入关分支，停在第一回合排队之前，把和重制同一个盘面写进原版内存，再让原版自己的帧循环打 N 回合。原版的逻辑一行不替换；外面给的只有玩家或设置能给出的输入（点掉对白、结束回合、选剧情选项、按设置关掉成长或启用随行队员）和随机种子。

两边逐步比对：谁行动、从哪格到哪格、做了什么、打谁，以及每一次随机抽取落在原版的哪个调用点。入口是 [`_enemy_level.py`](../tools/hsltools/probes/_enemy_level.py)，已经跑过的几批：

- **开局盘面**：127 场战斗开局时每个单位的 103 个字段，与原版同一时刻逐项对拍，剩下的差异逐行归因。报表由 `hsl generate opening_snapshot` 在有正版数据的机器上生成。
- **随机流**：重制用原版的随机数发生器，全局流和伤害流分开，裁判按调用点逐个对照抽取次序。
- **AI 首轮回放**：在分类器标出规则候选的 49 关里，把原版抽到的数原样喂给重制，重放原版首轮的每一步，确证的规则差异为 0 行。
- **行动种类**：127 关各打 3 回合，普攻、待机、追击、守候的出现频率与原版没有显著差异。

后两批的数字和做法见[原版裁判批量对照](evidence_packets/runtime_observations/oracle_batch/README.md)。演出和界面没法让程序当裁判，改用原版录屏逐帧对照，结论同样写进证据包。

## 证据分级

每条结论都标来源等级，新结论只用这七级：

- `resource-derived`：直接读自原版数据包里的表格、脚本和图，能说明资源在不在、字段值多少、脚本什么顺序。
- `static-derived`：读原版程序的指令得出，能说明函数行为、字段含义和公式。
- `runtime-measured`：原版跑起来实测，裁判对拍和录屏读数都算；只回答采样时问的那个窄问题。
- `user-confirmed`：熟悉原版的人明确确认过的身份、文字或行为，和其他来源分开记。
- `user-hypothesis`：玩家的记忆或推测，只当研究方向，不能直接照着实现。
- `provisional`：重制暂定。原版还没读到，写明范围和缺什么证据，以后换掉。
- `negative-evidence`：查过某个来源，没找到支持；只拦错误说法，不证明相反的机制成立。

测试通过只说明实现没回归，不说明和原版一样；写结论的其他规矩见 [CONTEXT](../CONTEXT.md#claim-rules)。

`game/` 下每个模块开头有一段 `## provenance:`，按规则、布局、文字、时序、声音五个维度各写一行等级和出处。照录屏目测的写 `runtime-reference`，原版没有、重制自己加的写 `remake-invented`。`resource-derived`、`static-derived`、`runtime-measured`、`runtime-reference` 这四种必须指向仓库里存在的证据文件，门禁会查。格式见 [ARCHITECTURE](ARCHITECTURE.md#provenance-headers)，全部模块的汇总在 [PROVENANCE](PROVENANCE.md)。

## 证据包

[证据包](evidence_packets/README.md)一篇只讲一个机制，结论先行：原版怎样、重制怎样、差在哪，每句带等级；要复核再往下看证据和复现命令。包头字段和正文六块的顺序见证据包首页，按主题或函数地址找包用 [KNOWLEDGE_INDEX](KNOWLEDGE_INDEX.md#evidence-packet-index)。

## 差异清单

[差异清单](evidence_packets/static_reverse/parity_gap_inventory.md)是探照灯，不是待办。每次检查它都从仓库重新量一遍来源：模块头里的 `remake-invented`／`provisional`，证据包里"未读／未复原"的句子，包头的暂定范围，[机制矩阵](MECHANICS_EVIDENCE_MATRIX.md)的每一行，录屏对账的差异类。每个来源要么归进一条差异，要么写明玩家为什么看不到，要么写明在哪里已经做掉。模块头、包头暂定范围、机制矩阵和录屏对账的来源没归类，检查就失败；证据包句子没归类只报警告，不挡门禁。

一条差异算"已照原版"，要三件事都到位：代码按原版改完；模块头的等级换成带出处的 `static-derived` 或 `runtime-measured`；证据包的结论改写成原版怎样、重制怎样。来源都消失了，这一条才从清单上下去。

条数会涨。原版读得越深，越会发现以前没意识到的暂定处，新来源一出现就要归类，所以清单常常先变长再变短。当前总数看清单页首。

## 有意不照原版的地方

默认就是原版。门禁、裁判、批量对照和自动对局只跑原版设置；唯一例外是快门禁在「舒適」预设下再跑一遍场景冒烟，只查脚本错误和卡死（见 [OPTIONS §7](OPTIONS.md#7-测试与门禁口径)）。

重制加了一层体验改良，每项是一张 `OPT-*` 选项卡，写明原版怎样、改良怎样、为什么，并链到差异清单或证据包。改良只能在原版路径上加一层，关掉时走的就是原版；演出类改良不许改变随机数的抽取次数和顺序。规则见 [OPTIONS](OPTIONS.md)。

开发用的开关（种子、机器人、停格、调试显示）只走环境变量和命令行，不进设置页，也不改产品默认。重制自有、原版没有的界面在模块头里标 `remake-invented`，会进差异清单。
