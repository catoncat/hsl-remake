# 规则数值手册

> 范围：重制版现行规则（`game/sim/`）与它读取的数据表；规则按原版程序核对，证据等级以各出处为准。所有除法都是整数除法（向零取整），`rand(n)` 返回 0..n−1。
> 规则变化时以代码和证据包为准；文中的「文件:行号」只帮助定位，代码一改行号就会漂，按同处写的函数名或常量名查，不按行号。表中数值由 `game/sim/` 公式在 Python 里重算并做蒙特卡洛估计，口径写在每张表前面。

## 0. 先记住的几件事

1. **普通攻击看「攻−防」**：差值 ≥10 时每下约等于差值的 85%（另有力量差修正）；差值 1–9 是 7–21 点的小区间；差值 ≤0 也保底 3–7 点。防御堆得再高也挡不住保底伤害。
2. **魔法完全不看防御**：只看施法者等级、精神、魔攻和目标的属性抗性（最多减 80%）。回复同一条公式，不乘抗性。magicOTHER 类（滅、裁等）不读抗性。
3. **命中几乎由武器决定**：命中值是装备命中值之和——武器 90–99，另有少数防具／饰品 +5～+10 或 −8；反应差最多 ±30，闪避直接相减，最低 10%。
4. **敌人等级跟着我方走**：敌方入场时以「我方登记队员平均等级」（本关在场的队员，阵亡的也算）为中心随机调级，只升不降，下限是模板四维推出的底级 B，上限 B＋R（原版前中期杂兵 R 14–28，后期杂兵 48–75，Boss 30–80），且升级数不超过四维余量（魔騎士、黑暗法師最多 61 级，1.10）。所以一关的难度主要由选哪些模板、多少人、什么装备决定；要写死等级就把 R、D 设 0。
5. **队员第一次登场的等级只认四维和**：＝1＋ceil((四维和−52)/5)，角色行的 `level` 栏不起作用；之后的等级随经验涨、在同一战役内承接。原版中后期入队的嚎 11、雷特 12、克羅蒂 24 与当时敌方底级（8–12、18–26）相当。
6. **经验按每次动作结算，越级打怪奖励极高**：低于目标等级时，经验约为 伤害×min(5, 等级差)＋击杀奖励；高于目标时被 (等级差×80%) 除。升级阈值 (L+1)×50，封顶 2000。经验的六到八成来自击杀（kill_exp 随入场调级最多 ×2.5），同级魔騎士类打死 2.5–3 个就升一级，L39 以后也是如此；经验按出场人数平分，2 人小队涨级是 9 人全队的 3.6–5.3 倍（2.6；L50 起步全灭时最少，2 人很快练过魔騎士、黑暗法師的 61 级上限）。
7. **每级 5 点四维，转职看四维到不到上限−50**：九名队员按最省的加点都在 L21 达到一转条件；雷歐納德、緹娜二转最早 L41。转职给大量固定加值（劍豪 攻+40、狂戰士 HP+80 等）。
8. **中后期强度的主轴是装备**：同一等级下，初始装和斐達克商店装的前排，对同级魔騎士从「近二十下」变成「三下左右」；同级杂兵对换装后的前排多半只能打保底伤害（2.2 对 2.3）。宝箱和剧情给的终盘武器比斐達克最好的再高 70–190 攻击（2.4 末）。
9. **原作通关约 L33–47（推算）**：不打遭遇战 33–34，遭遇战全打 46–47；一转条件 L21 在第二幕前半达到，二转条件 L41 只有大量打遭遇战才在第三幕后段达到（3.6）。

## 1. 公式

### 1.1 面板刷新（每次升级、加点、换装、状态变化后重算）

出处：`game/sim/ProgressionRules.gd:227`（`refreshed_growth_stats`）、`game/sim/JobStatsRules.gd:89`（`base_values`）、职业公式表 `content/generated/hsl/roles/job_formulas.json`（手写源 `content/authored/roles/job_formulas.json`）；原函数 `0x448840`，证据 `docs/evidence_packets/static_reverse/original_job_stats.md`、`original_growth_refresh.md`。

```text
最大HP  = Σ职业HP项 + 源hit_point + 装备max_hp           （职业项里的「L(我方)」只对我方阵营单位取等级，敌方取 0）
最大MP  = Σ职业MP项 + 源magic_point + 装备max_mp         （没有任何魔法的单位 MP 上限为 0）
攻击    = Σ职业攻击项 + 源attack_power + 等级攻击加成(L) + 装备attack + 攻击增益
防御    = Σ职业防御项 + 源defense + 装备defense + 防御增益
魔攻    = min(封顶, Σ职业魔攻项)，超过折点的部分减半，+职业加值 + 源magic_attack_power + 装备magic_attack
速度    = Σ职业速度项 + 源speed + 装备speed               （决定行动顺序，降序插入排序）
抗性[地水風火心] = clamp(源基础抗性 + min(职业封顶, p·精/100 + 體/div) + 装备 + 魔障壁, 0, 80)
命中    = 装备 hit_rate 之和（武器 90–99；冥王之鎧／邪眼假面／影殺之靴 +10、貓眼戒指 +5、墨鏡 −8）
闪避    = 源avoid_hit_ratio + 装备
反击率  = (源attack_back 为 0 时取 12，否则取源值) + 装备
暴击率  = (源attack_damagex2 为 0 时取 8，否则取源值) + 装备
移动    = clamp(源基础移动 + 装备, 0, 12)

等级攻击加成(L)：L<10 → L；10≤L<20 → 10+(L−10)/2；L≥20 → 15+(L−20)/4      （JobStatsRules.gd:118）
```

「源」是角色模板（PLAYERS 行）里的固定字段，转职时目标模板的源字段会累加进来（见 1.9）。各职业的公式项见本节末「职业公式总表」。

### 1.2 命中与闪避

出处：`game/sim/CoreCombatRules.gd:113`（`hit_chance`）、`:227`（`resolve_attack`）；原函数 `0x409a60`、抽样 `0x403ef8/0x403f47`；`docs/first_battle_core_logic_evidence.md`「Hit chance」。

```text
d       = trunc((攻方反应 − 守方反应) / 2)，夹到 [−30, 30]
raw     = clamp(攻方命中 + d, 20, 100)
基础命中 = max(raw − 守方闪避, 10)
实际命中 = min(100, 基础命中 + 攻方补偿累积)
判定     rand(100) < 实际命中 → 命中
补偿     普通攻击落空后 补偿 += 基础命中/10；打出正伤害后清零
```

闪避是直接减法：漢克斯（盜賊）源闪避 26，对命中 96 的敌人基础命中约 70%。命中与伤害公式里都没有地形或高低差项；地形只影响移动（高差 ≥3 不可走，`game/sim/TacticalGridRules.gd`）和技能的射程／范围格（`game/sim/loop/BattleLoopCombat.gd:46–52`）。

### 1.3 普通攻击伤害

出处：`game/sim/CoreCombatRules.gd:161`（`preview_damage`）、`:140`（`variance_bonus`）、`:279`（`damage_floor`）；原函数 `0x409be0`、`0x409af0`；`docs/evidence_packets/static_reverse/original_ordinary_special.md`。

```text
base = 攻方攻击 − 守方防御
s    = trunc((攻方力量 − 守方力量) / 2)，夹到 [−20, 30]
若 base ≤ 0：   E = 3 + rand(5)（3..7），s 取 max(s, 0)
若 1 ≤ base ≤ 9：E = rand(base+4) + (base≤2 ? 7 : base≤6 ? 8 : 9)，s 取 max(s, 0)
若 base ≥ 10：  E = base；s 为负时不低于 −E/2
伤害 = E + s − rand(E·30/100) − rand(|s|/2) + rand(|s|/2)
伤害 ≤ 0 时改取 3..10 的小保底
武器带属性时再加：roll = lo + rand(|hi−lo|)（0 记 1），v = roll + rand(roll/2)（不足 3 补到 3..5），
                 v × (100 − min(80, 守方该属性抗性)) / 100
最终至少 1
```

经验口径：base≥10 时平均伤害 ≈ 0.85×base + s。反击伤害再 ×80%（至少 1）；守方佩戴「HP 伤害减半」装备时再减半（至少 1），技能伤害不走这一步（`CoreCombatRules.gd:241–244`）。

### 1.4 暴击（attack_damagex2）

出处：`game/sim/CoreCombatRules.gd:268`（`critical_impact`）；原 `0x403f39`。

```text
命中后另抽 rand(100)+1 ≤ 暴击率 → 暴击
暴击：伤害 < 6 时反复 +2+rand(5) 直到 ≥ 6；lo = 伤害×150/100；伤害 = min(32767, lo + rand(|2×伤害 − lo|) + 1)
```

即暴击伤害为原伤害的约 1.5～2 倍。默认暴击率 8%；模板写了非零值就用模板值（雷歐納德 14、緹娜 18、漢克斯 24、咕嚕 26、克羅蒂 26）。暴击不改变用于气力计算的「排队伤害」。

### 1.5 反击（attack_back）

出处：`game/sim/CoreCombatRules.gd:287`（`attack_back_triggered`）及 PlayLoop 交锋；原 `0x4423c0`、`0x444602`；`docs/first_battle_core_logic_evidence.md`「Counter call-site recovery」。

```text
条件：本次是普通攻击且允许反击；守方没有 no_attack；守方武器射程覆盖攻方所在格；守方未麻痺；
      rand(100)+1 ≤ 守方反击率
时机：主攻结算后，守方仍存活才反击一次；反击伤害 ×80%（至少 1），反击不会再引发反击
```

默认反击率 12%；嚎（鬥士）源值 42。弓手、法师被近身时能否反击取决于武器射程格。

### 1.6 魔法伤害与回复

出处：`game/sim/NativeMagicRollRules.gd:10`（魔法通道）、`game/sim/SupportMagicRules.gd`（回复／驱散）、`game/sim/SpecialDamageRules.gd:58`（特殊技通道）；原 `0x40a7b0`、`0x40aa80`；证据 `original_magic_damage.md`、`original_support_magic.md`、`original_special_element.md`。

魔法（MAGIC 表，消耗 MP）：

```text
命中 = 法术hit_ratio + 施法者补偿累积 + 装备魔法命中加成；rand(100)+1 > 命中 → 落空（目标 no_attack 时必中）
       落空后补偿 += 抽值/10；命中后清零
S    = lo + h − rand(h+1) + rand(h+1)，h = (hi−lo)/2          （三角分布，均值 (lo+hi)/2）
精'  = 精 < 36 ? 精/2 : (精−36)/4 + 18
值   = (clamp(施法者等级, 1, 80) + 精' + S) × 魔攻 / 100；不足 3 补到 3..5
攻击法术：值 × (100 − min(80, 目标该属性抗性)) / 100；回复（治癒之水等）不乘抗性，且以缺失 HP 为上限
```

特殊技（SPECIAL 表，消耗气力 ST）：

```text
命中 = hit_ratio + 补偿累积；抽法同上
值   = max(lo, S) + rand(L×180/100) + rand(L×150/100) + 體/8 + 精/4 + 反/3      （L 夹到 1..120）
值   = 值 × attackpow_ratio / 100；不足 3 补到 3..5
地水風火心五系再乘 (100 − min(80, 抗性))/100；magicOTHER 类不乘
```

两条通道都**不读目标防御**；特殊技也不读魔攻。

### 1.7 经验获取

出处：`game/sim/ExperienceRules.gd:56`（`from_contribution`）、`:82`（`record`）；原 `0x40a5d0`；`docs/evidence_packets/static_reverse/original_experience.md`。

```text
贡献 C：普通／技能／攻击法术 = 实际扣除的 HP（超杀不算）；治疗 = 实际回复量/2；驱毒 = (剩余回合+1)×12；
        施毒 = 实际增加的回合×10；禁魔 = 实际增加的回合×5
K = 目标被打死时的 kill_exp（模板值，入场调级会放大），否则 0
d = 行动者等级 − 目标等级
d ≥ 0：子总 = (C×40/100 + K + rand(C/2)) × 100 / (clamp(d,1,5) × 80)
d < 0：子总 = min(5, −d) × C + K
EXP  = max(1, 子总 − rand(子总×30/100))，C=0 时为 0
连杀：本次击杀时 ×(100 + 50×min(8, 此前连杀数))%；连杀数在每次击杀的动作后 +1，一次动作没有击杀（或只靠反击击杀）就清零；非致死的反击也清零
装备 experience_double：整次动作合计 ×2
```

同等级打一下 20 伤害约得 13 EXP，高 2 级约 7；低 3 级打同样伤害约得 51 EXP，再加击杀奖励。经验的大头是击杀：L40 打死同级魔騎士约 680 EXP，其中 kill_exp 约占八成（速查见 2.6）。没有整场胜利经验池；各目标经验合并后整次入账再查升级。

### 1.10 入场调级（敌方等级怎么来）

出处：`game/sim/EntryGrowthRules.gd:18`（`inferred_level`）、`:62`（`propose`）；原 `0x40e800`、`0x40e870`；`docs/evidence_packets/static_reverse/original_auto_growth.md`。参数 R／D 在 `content/generated/hsl/roles/entry_growth.json` 的 `parameters`（PLAYERS 的 level_adjust_range／level_adjust_disp_range）；脚本 `actSetPrevInsertObjectAdjustLevel` 可对单个增援覆盖。

```text
底级 B = 1 + max(0, ceil((力+反+精+體 − 52) / 5))
我方队员（kind3）只取 B，不随机上调
其它单位，R 与 D 不全为 0 时：
  lo0 = max(1, B−R)；hi0 = max(lo0+1, B+R)；c = clamp(我方登记队员平均等级, lo0, hi0)
  low = max(1, c − min(4, D))；high = max(low+1, c + D)；W = high − low + 1
  目标 = low + rand((W+1)/2 + 1) + rand(W/2)
  目标 > B 时升 Δ = 目标 − B 级：四维按配额加 Δ×5（升级数夹到四维余量；某一级配额放不下时四维全部填到上限）；源 HP +(250..349)×Δ/100、MP +(150..299)×Δ/100、
  速度 +(20..39)×Δ/100、攻击 +(50..109)×Δ/100、魔攻 +(10..19)×Δ/100；kill_exp 与金币按 Δ 放大；HP/MP 回满
```

D=1..4 时目标均值≈c，D=0 或 ≥5 时≈c+0.5；散布宽度约 c−min(4,D) 到 c+D。R：前中期杂兵 14–28，海鬥士 37、死靈騎士 48，后期杂兵魔騎士 52／狂戰士 55／黑暗法師 59／魔騎兵 75，Boss 30–80（全表见 3.5）。所以敌方等级基本等于我方平均等级，例外有三种：我方低于 B 时敌方停在 B（经验按 1.7 放大）；我方高于 B＋R 时敌方停在 B＋R 附近（经验按 1.7 打折），原版一般兵（B1·R18）、凶牙鬼（B2·R16）最多 21 级，到第三幕已跟不上；四维余量不够时等级到不了目标，升级数夹到 ⌈Σ(职业上限−四维)/5⌉，魔騎士、黑暗法師最多 61 级（kill_exp 与源 HP 增量仍按目标 Δ 放大）。R＝D＝0 时完全不调级（`game/sim/EntryGrowthRules.gd:91`），等级就是 B。

## 3. 原作曲线

### 3.1 口径

- 数据：127 场原版战斗（主线与支线 49 场＋遭遇战 78 场；重制手写的第 200 关不计）。开场单位取 `content/battles/*.json` 的 `playable_units`，增援取各关胜负脚本里的 `actInsertObject*`（`scenario_rules.status_timelines`，失败段不计），模板四维推出的底级 B 见 1.10。统计脚本只读这些文件，没有跑游戏。
- 顺序：开局三场按 `docs/BATTLE_NAMES.md`，其后按各关 WINFAIL 的 `actSetNextPlayLevelEvent` 链与 `docs/ORIGINAL_STORY.md` 的剧情顺序排；9xx 支线排在它跳回的那一关附近，遭遇战归到同地图的主线关。终章三条结局线并列。
- 「我方出战」：关卡指定成员的照写；关卡写的是「全部登记队员」（生成件里是九人夹具）的，按剧情入队点折算成当时人数。敌／我＝（开场＋增援敌人）÷我方出战人数。
- **我方实际等级原版没有写死**：队员一入队就跟着玩家的经验走，原版数据里能读到的只有入队等级（四维推出的 B）和转职门槛。下面用两条线代替「我方大致等级」：入队等级＋最早转职等级（3.2），和敌方底级 B（3.3、3.4）。由于入场调级（1.10），敌方实际等级≈max(B, 我方平均等级)。
- 自动对局 `content/generated/hsl/development/autoplay/results.json`：贪心策略、固定种子、**每关用开局名册单独开打**（队员停在入队等级、初始装备，雷歐納德阵亡即败），文件自己注明「not evidence about original balance」。只能当「入队等级＋初始装备够不够」的粗信号，不是原版难度证据。

- 这是规则下的期望推算，不是原版平衡的证据：打掉几成、经验怎么分都是假设；实玩里补刀集中在前排，前排会比后排高几级。

分层与命令见 [MODDING_LEVELS](MODDING_LEVELS.md)（下称「逐步表」，# 号沿用它的编号）与 [MODDING](MODDING.md) §1、§4。下表只讲写续集关卡最常碰到的四类：新角色、新职业、敌人的等级与数值、增援。「只写数据」指改 `content/authored/` 下的文件再跑 `python3 tools/hsl.py generate …`；「改代码」指要动 `game/` 或 `tools/hsltools/`。

### 4.1 新角色（我方）

| 想做什么 | 类型 | 怎么做、限制 |
|---|---|---|
| 新角色的四维、职业、源字段、装备、初始技能、AI、开场气力、kill_exp、抗性 | 只写数据（#10、#12） | `content/authored/roles/characters.json` 加一行（字段同 PLAYERS，值写字符串），code 加进 `roster.json`。源字段即 1.1 的「源」：`hit_point`／`magic_point`／`attack_power`／`magic_attack_power`／`defense`／`speed`／`avoid_hit_ratio`／`attack_back`／`attack_damagex2`；装备栏写原版 ITEM 代号 |
| 开场等级 | 只写数据，但**只能经四维和** | 开场时我方等级一律由四维和推出（`game/sim/InitialRosterGrowthRules.gd:105`，公式见 1.10），行里的 `level` 栏不决定战斗中的等级：示范 102 蕾雅写 `level 3`，四维和 74，开场是 L6。要某个等级 L，四维和至少 52＋5×(L−1)：L10→97、L20→147、L30→197、L40→247 |
| 高等级、已转职的老角色（例：緹娜、漢克斯） | 只写数据 | 新开一个代号写成目标状态：`job` 直接写转职后的职业（緹娜 86 神官／87 公主，漢克斯 89 暗殺者），四维按目标等级写，源字段写成「基础行＋转职模板」累加后的值（见 2.4 开头的累加量）。外观用 `level.json` 的 `presentation.sprite_aliases` 借 002／011／020、004／013 的帧（#14） |
| 归队角色入队时的等级、职业、装备 | 只写数据 | 角色第一次在本战役出场的那一关按角色行建（`game/sim/InitialRosterGrowthRules.gd:96–115`）：等级只由四维和推出（上两行），职业取 `job`（可以直接写一转、二转职业），装备取 `weapon_equip`…`other2_equip`（原版 ITEM 代号，本职业要能装）。之后各关按 `game/sim/CampaignCarryRules.gd:53` 承接等级、经验、待分配点、装备、物品、已学技能与转职记录 |
| 归队角色入队时已会的技能 | 只写数据，有两处限制 | 角色行的 `magic_earth`…`magic_other`、`special_earth`…`special_other2` 每格可写逗号分隔的多个招式名（PLAYERS.TXT 原有「熾焰鳥,魔燒焚燼,怒炎魔獄燋」这种写法，解析在 `tools/hsltools/data/skill_book.py:163`），写进去的入队即会。没写的：魔法要等入队后第一次升级，按学习表把等级已达标的一次补齐（`game/sim/loop/BattleLoopRewards.gd:69`）；特殊技在每次确认加点时最多补一个（`game/sim/LearningRules.gd:89`）。角色行不能预填 `learned_skills`（建角色时报 `already_progressed_initial_actor`，`InitialRosterGrowthRules.gd:47`／`:99`） |
| 入队等级对上当时的队伍 | 只写数据，但要自己估 | 入队者的等级在角色行里写死；原班人马的等级由经验决定，经验按出场人数平分（2.6），人少的前几关升得快。原作的做法见 3.2（中后期入队等级≈当时敌方底级） |
| 直接改原版 002／004 行 | 只写数据，但影响第一章 | 覆盖层 `content/authored/overrides/PLAYERS.json` 是全局的，第一章也会变（`docs/MODDING.md` 覆盖层段）；另开新代号则不影响第一章 |
| 把第一章存档里的等级、装备带进新战役 | 改代码（未找到入口） | 登记的新战役存档独立（逐步表 #23），关与关之间的承接只在同一战役内（`content/battles/campaign.json` 的 `carry_policy`）；没有查到跨战役导入队伍的数据入口 |
| 新角色走命運神殿的转职链、战斗内转职 | 改代码 | 城镇转职目标是 `game/sim/JobUpRules.gd` 的常量 `TOWN_TARGETS`（001→010 等）；战斗内 `actPlayerJobUpProcess` 读关卡的 `job_up_targets`／`job_up_templates`，第一章由 `tools/hsltools/levels/battle.py:1359–1361` 从关卡档案写入，作者关生成器写的 `scenario_rules` 不带这两项（`tools/hsltools/levels/authored.py:587–589`），作者关里这个 token 找不到目标。直接以转职后的职业入队则用不到转职链（「尾声之后」一行）。转职后的城镇改写表可以按战役另写（逐步表 §6「转职后哪座城怎么变」，只写数据） |
| 新外观、切入、头像 | 只写数据，新图必须有素材（#14–#16） | `content/authored/actors/<代号>/` |

### 4.2 新职业

| 想做什么 | 类型 | 怎么做、限制 |
|---|---|---|
| 新职业的公式、四维上限、自动配额、魔攻、抗性 | 只写数据（#11） | `content/authored/roles/job_formulas.json` 的 `jobs` 加一行，项的写法同第 1 节职业公式总表；标 `"evidence_tier": "authored"` |

### 4.3 敌人的等级与数值

| 想做什么 | 类型 | 怎么做、限制 |
|---|---|---|
| 用原版敌人模板 | 只写数据（#4、#6） | `level.json` 的 `units[]`（开场）或 `objects`（增援）写原版 PLAYERS 代号，如 049 魔騎士 |
| 新敌人模板（新数值、新名字） | 只写数据（同 #10） | characters.json 一行，`mode` 写 pmEnemy；四维、源字段、装备、AI、`kill_exp`、`gold`、`level_adjust_range`／`level_adjust_disp_range` 全在行里。示范第 200 关的敌人借的是原版 036，新敌人模板这条路没有端到端示范 |
| 敌人等级 | 只写数据，经「四维和＋R／D」 | 底级 B 由四维和推出；R／D 决定往上跟我方平均等级跟多远（1.10）。三种写法：**写死**——四维和按目标等级写、R＝D＝0，此时完全不调级（`game/sim/EntryGrowthRules.gd:91`），等级就是 B；**跟随**——R 写大（原版后期杂兵 52–75）、D 写 2–3，敌方≈我方均级 ±D，但最多到 B＋⌈Σ(职业上限−四维)/5⌉（四维余量）；**跟随但封顶**——R＝封顶等级−B、D＝0，敌方等级是 min(均级, B＋R) 或再 +1（各一半），不低于 B |
| 跟随时看的「我方平均等级」 | 规则，数据改不了 | 本关在场队员的整数平均，阵亡的也算，不在本关的不算（1.10 末段）。两人小队时就是这两人的平均 |
| 单个敌人改 R／D | 增援只写数据；开场单位要改代码 | 增援：winfail 在 `actInsertObject` 后紧跟 `actSetPrevInsertObjectAdjustLevel,R,D`，编进这次插入（`game/sim/WinfailCompiler.gd:339–341`），出生时优先于模板值（`game/sim/ReinforcementGrowthRules.gd:16–25`），`0,0`＝不调级。开场单位：第一章靠 EVEF 实例覆写（`evef_instance.overrides`，`content/schema/unit.schema.json`），作者关 `level.json` 的单位只收 `id`／`actor`／`token`／`role`／`cell`（`tools/hsltools/levels/authored.py:148`），生成器不写实例覆写，要改生成器；不改代码的变通是给这个敌人单开一行角色模板（复制原模板，改四维与 R／D） |
| 关掉某关的自动调级 | 只写数据（逐个模板） | 没有按关的开关，调级只看每个单位自己的 R／D（`EntryGrowthRules.gd:91`）。做法是本关用到的敌方模板都写 R＝D＝0、增援都跟 `actSetPrevInsertObjectAdjustLevel,0,0`。模板是全局的，改原版模板会连带第一章，新战役用自己的模板行。反方向另有 `actAdjustAllPlayerLevel`（让在场单位按当时队伍再调一次，全库只有 STORY006 用） |
| 直接写某个敌人的 HP、攻击 | 不能直接写 | 非我方单位开场都会走入场调级，末尾按公式刷新并把 HP 设到上限（`game/sim/ReinforcementGrowthRules.gd:95–96`），`initial_state` 里写的 `max_hp` 会被覆盖。要加血加攻，改角色行的源字段 `hit_point`／`attack_power`，或换装备 |
| 敌人的 AI（找谁、多远、何时补血） | 只写数据 | 角色行的 `find_type`／`find_range`／`ai_*`（`docs/MODDING.md` §4 例二）；单个单位覆写 `evef_instance.overrides` 的 `find_type`／`find_range`／`wait_round`／`fixed_point` |
| 敌人掉落、金币 | 只写数据 | `gold`、`item1..8`；入场调级会按 Δ 放大金币与 kill_exp（1.10） |

### 4.5 设计时顺带要记的

- 公式本身（第 1 节）是第一章的原版公式，作者关不改它；改公式属于改代码，原版对拍检查会报不一致（逐步表 §10）。
- 自动对局（`tests/run_autoplay_sweep_tests.gd`，`HSL_CAMPAIGN=<id> HSL_AUTOPLAY_LEVELS=<关号>`）能确认一关打得通，不是难度证据；新关卡的难度要靠第 2 节的表估，再实玩。
